# 04. 앱 구현 지시서 — 출시 가능한 안드로이드 앱

## 목표
프로토타입(02)과 레벨 팩(03)을 바탕으로, 그래픽·사운드·저장·설정을 갖춘 **안드로이드 앱(AAB)**을 만듭니다.

## 입력
- `packages/core` (03에서 분리한 공유 규칙 엔진). 아직 없으면 `reference/src`를 그대로 씁니다.
- `out/pack-01.json` (03의 결과). 아직 없으면 `reference/src/cli.ts`로 만든 JSON 몇 개로 대신합니다.
- `01_게임기획서.md` 3·5·6·8·12장
- 아트 리소스: 씨앗/싹/꽃 스프라이트(칸당 1장씩, 흰색으로 그려 색은 코드에서 입힘), 물방울, 슬롯 틀, 배경, 앱 아이콘

## 기술 스택
| 영역 | 선택 | 비고 |
|---|---|---|
| 언어/빌드 | TypeScript + Vite | 엔진·생성기와 같은 언어 |
| 렌더링 | PixiJS (v8 계열 최신 안정판) | 스프라이트, tint로 색 입히기, 파티클 |
| 앱 포장 | Capacitor (최신 안정판) + Android 플랫폼 | `npx cap add android` |
| 저장 | `@capacitor/preferences` | 진행도, 설정 |
| 진동 | `@capacitor/haptics` | 개화/실패 피드백 |
| 사운드 | Web Audio (또는 howler.js) | 개화 음은 링마다 음 높이가 오르게 |
| 테스트 | Vitest(엔진/상태), Playwright(웹 화면 E2E) | |

> 버전은 작업 시점의 최신 안정판을 씁니다. 안드로이드 `targetSdkVersion`은 **Google Play 현재 요구 수준 이상**이어야 합니다. 2026년 8월 31일부터 신규 앱과 업데이트는 Android 16(API 36) 타깃이 요구됩니다. 시작 전에 [대상 API 요구사항](https://developer.android.com/google/play/requirements/target-sdk)을 다시 확인하세요.

## 폴더 구조
```
bloom-wave/
├─ packages/core/         # 규칙 엔진, 솔버, 생성기 (03)
├─ tools/levelgen/        # 레벨 생성 CLI (03)
└─ app/
   ├─ src/
   │  ├─ main.ts          # Pixi 앱 생성, 씬 전환
   │  ├─ scenes/          # Title, StageMap, Game, Garden(도감), Settings
   │  ├─ game/
   │  │  ├─ GameController.ts   # core 엔진 호출, 되돌리기 스택, 입력 잠금
   │  │  ├─ BoardView.ts        # 칸 스프라이트, 상태별 텍스처
   │  │  ├─ DropView.ts         # 물방울, 슬롯, 대기열
   │  │  └─ WavePlayer.ts       # TickEvent[] → 타임라인 재생
   │  ├─ save/            # Preferences 래퍼, 저장 스키마 버전
   │  ├─ audio/  i18n/  ui/
   │  └─ levels/pack-01.json
   ├─ public/assets/      # 스프라이트 아틀라스, 사운드
   ├─ android/            # Capacitor가 생성
   └─ capacitor.config.ts
```

## 작업 단계

### 1단계. 골격
1. `npm create vite@latest app -- --template vanilla-ts`, `npm i pixi.js @capacitor/core @capacitor/preferences @capacitor/haptics`, `npm i -D @capacitor/cli`.
2. `npx cap init "Bloom Wave" com.<회사또는이름>.bloomwave --web-dir dist`. **패키지 이름(applicationId)은 출시 후 바꿀 수 없으니** 여기서 확정합니다.
3. 세로 고정 화면, 논리 해상도 1080×2340 기준 스케일링, 안전 영역(노치) 여백 처리.

### 2단계. 게임 화면
1. **GameController**: 레벨 로드 → `createState`. 고정 간격 틱 타이머(기본 300ms — 2026-11-04 변경, Pixi `Ticker`의 누적 시간으로 계산)가 `isActive(s)`일 때 `tick(level, s)`를 호출하고 `TickEvent`를 WavePlayer에 넘깁니다. 대기열 탭은 틱 사이 언제든 받아 `deploy(level, s, lane)`을 호출합니다(`GameController.tap(lane)`, 대기열은 3줄 이상). 탭 가능 여부는 `legalActions(s, level.options)`로만 판단합니다. 앱이 백그라운드로 가면(`@capacitor/app`의 `pause`) 타이머를 멈추고 일시정지 화면을 띄웁니다. **규칙 로직은 core만 씁니다.** 화면 코드에서 규칙을 다시 구현하지 않습니다.
2. **BoardView**: 보드 영역에 맞춰 칸 크기를 계산합니다(16×16이면 칸 하나가 약 40dp). 칸 스프라이트 3종(씨앗/싹/꽃)에 `tint`로 팔레트 색을 입힙니다. 보드는 터치를 받지 않습니다(자동 확산).
3. **WavePlayer**: 탭한 물방울은 대기열 → 슬롯으로 비행시킵니다(비행 중에도 엔진 상태는 이미 슬롯에 있음). 틱마다 슬롯에서 링 칸으로 물줄기, 개화 칸 `scale 0.6→1.15→1`(링 안에서 발아 순서대로 20ms 시차), 8방향 전염 칸에서 싹이 돋는 연출, 슬롯 숫자 감소. 각 틱의 연출은 다음 틱 전에 끝나도록 틱 간격 안에 맞춥니다. 개화음 피치가 틱마다 반음씩 올라갑니다. 입력은 잠그지 않습니다.
4. **DropView**: 좌 2·우 2 슬롯, 대기열(탭 가능한 물방울 강조, 최대 7개 표시 후 `+N`). 맨 앞 물방울의 색과 같은 발아 칸을 미리 강조하고, 없으면 "대기" 표시. 슬롯이 3칸 이상 차면 경고 색.
5. **결과 화면**: 클리어 시 Full Bloom 연출과 "완성!"(별점 없음, 2026-11-04). 완성 화면을 떠날 때 전면 광고(`monetize/ads.ts`, 광고 제거 구매 시 건너뜀). 실패 시 [다시 하기] / [되돌리기], 광고 없음.
6. **되돌리기**: 탭할 때마다 탭 직전 `cloneState` 스냅샷을 쌓습니다(최대 50개). 되돌리면 그 시점으로 돌아가 일시정지 상태로 시작합니다.

### 3단계. 메타
1. **StageMap**: 팩의 레벨을 순서대로 표시. 별점과 잠금 상태.
2. **Garden(도감)**: 클리어한 그림을 꽃 상태로 모아 보기.
3. **Settings**: 사운드, 진동, 틱 속도(기본/느리게), 언어(한/영), 개인정보처리방침 링크, 버전 표시.
4. **저장**: `{ schema: 1, unlocked, stars: {levelId: n}, settings }`를 Preferences에 JSON으로 저장. 레벨을 끝낼 때마다 저장합니다. 스키마 버전 필드를 꼭 둡니다(업데이트 대비).

### 4단계. 안드로이드
1. `npm run build && npx cap add android && npx cap sync android`.
2. `android/app/build.gradle`: `targetSdkVersion`/`compileSdkVersion`을 현재 Play 요구 수준으로, `versionCode` 1, `versionName` "1.0.0".
3. 아이콘/스플래시: `@capacitor/assets`로 1024×1024 원본에서 생성. 적응형 아이콘 전경/배경을 분리합니다.
4. 뒤로 가기 버튼: `@capacitor/app`의 `backButton` 이벤트로 씬 뒤로 가기, 타이틀에서는 종료 확인.
5. 오프라인 동작: 모든 리소스를 앱에 포함합니다. 네트워크 권한이 필요 없으면 매니페스트에서 빼서 데이터 보안 양식을 단순하게 만듭니다.
6. 실기기 테스트: 저사양 기기(RAM 3GB급)에서 16×16 레벨의 웨이브가 60fps 근처를 유지하는지 확인합니다.

### 5단계. 품질
- Vitest: core 테스트 전부 + GameController(되돌리기, 저장/불러오기).
- Playwright: 웹 빌드에서 테스트용 수동 틱 모드(`?manualTick=1`)를 켜고 레벨 1~5를 솔버 해법(deploy/tick 수순)대로 자동 플레이해 클리어되는지 확인(회귀 테스트). 실시간 타이머에 의존하면 테스트가 흔들리므로 꼭 수동 틱 모드를 둡니다.
- 팩 무결성: 빌드 전에 `levelgen verify`를 실행하고, 실패하면 빌드를 막습니다.
- 크래시/오류 수집은 MVP에서는 Play Console 안드로이드 바이탈로 충분합니다. 외부 SDK를 넣으면 데이터 보안 양식에 반영해야 합니다.
