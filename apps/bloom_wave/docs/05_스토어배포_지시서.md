# 05. Google Play 배포 지시서

> **기록용 (2026-11-04 Flutter 전환 이전 기준).** 이 문서의 TypeScript·npm·Capacitor 세부는 지금 코드와 다릅니다. 현재 구조는 [../README.md](../README.md)를 보세요.

## 목표
04에서 만든 앱을 Google Play에 **내부 테스트 → 비공개 테스트 → 프로덕션** 순서로 출시합니다.

> 정책과 화면은 자주 바뀝니다. 각 단계 전에 Play Console 도움말을 다시 확인하세요. 아래 내용은 2026년 10월 기준입니다.

## 전체 일정 (개인 개발자 계정 기준)
| 주차 | 할 일 |
|---|---|
| 0주 | 개발자 계정 생성·본인 인증 (승인까지 며칠 걸릴 수 있음) |
| 1주 | 앱 생성, 서명, 내부 테스트 업로드, 스토어 등록정보·정책 양식 작성 |
| 1~3주 | **비공개 테스트: 테스터 12명 이상이 14일 연속 참여** (2023년 11월 이후 만든 개인 계정의 필수 조건) |
| 3주~ | 프로덕션 액세스 신청 → 심사 → 단계적 출시 |

테스터 12명은 가장 시간이 오래 걸리는 단계입니다. **0주차부터 지인 테스터 목록(Gmail 계정)을 모아 두세요.**

## 1단계. 계정과 서명
1. [Play Console](https://play.google.com/console)에서 개발자 계정을 만듭니다. 등록비는 1회 25달러입니다. 개인 계정은 본인 인증, 조직 계정은 D-U-N-S 번호가 필요합니다. 연락처와 주소 인증까지 끝내야 앱을 만들 수 있습니다.
2. Android 개발자 인증(패키지 이름 등록) 관련 안내가 콘솔에 표시되면 그대로 완료합니다.
3. **업로드 키 생성** (한 번만, 절대 분실 금지):
   ```bash
   keytool -genkeypair -v -keystore upload-key.jks -alias upload \
     -keyalg RSA -keysize 2048 -validity 10000
   ```
   - `upload-key.jks`와 비밀번호는 저장소에 넣지 말고 비밀번호 관리자와 별도 백업에 보관합니다.
   - `android/keystore.properties`(git 제외)에 경로·비밀번호를 적고 `build.gradle`의 `signingConfigs.release`에서 읽습니다.
4. **Play 앱 서명**을 사용합니다(기본값). Google이 앱 서명 키를 보관하고, 우리는 업로드 키로만 서명합니다. 업로드 키를 잃어버려도 재설정할 수 있습니다.

## 2단계. 릴리스 빌드
```bash
cd app
npm run build
npx cap sync android
cd android
./gradlew bundleRelease          # → app/build/outputs/bundle/release/app-release.aab
```
- 업로드할 때마다 `versionCode`를 1씩 올립니다. 같은 번호로 다시 올릴 수 없습니다.
- `minifyEnabled`(R8)를 켰다면 릴리스 빌드를 실기기에서 한 번 더 확인합니다.
- `targetSdkVersion`이 Play 요구 수준 미만이면 업로드가 거부됩니다(2026년 8월 31일 이후 API 36).

## 3단계. 앱 만들기와 내부 테스트
1. Play Console → **앱 만들기**: 앱 이름, 기본 언어(한국어), 게임, 무료.
2. **테스트 → 내부 테스트**에서 AAB를 업로드하고, 본인 계정을 테스터로 추가해 설치를 확인합니다. 심사 없이 몇 분 안에 배포됩니다.

## 4단계. 스토어 등록정보
| 항목 | 규격 |
|---|---|
| 앱 이름 | 30자 이내 |
| 간단한 설명 | 80자 이내 |
| 자세한 설명 | 4000자 이내 (규칙 소개, 레벨 수, 오프라인 플레이 등) |
| 앱 아이콘 | 512×512 PNG |
| 그래픽 이미지 | 1024×500 PNG/JPG |
| 휴대전화 스크린샷 | 2장 이상 (권장 4~8장, 세로 9:16 이상) |
| 카테고리 | 게임 → 퍼즐 |
| 연락처 이메일 | 필수 |
- 영어 등록정보도 함께 만들면 해외 노출에 유리합니다.
- 스크린샷은 Playwright로 웹 빌드에서 자동 촬영한 뒤 기기 틀을 씌우면 빠릅니다.

## 5단계. 정책 양식 (앱 콘텐츠)
1. **개인정보처리방침 URL**: 데이터를 수집하지 않더라도 필요합니다. GitHub Pages 등에 "수집하는 개인정보 없음, 진행도는 기기에만 저장" 내용으로 게시합니다.
2. **데이터 보안**: 외부 SDK가 없고 진행도를 기기에만 저장하면 "수집·공유하는 데이터 없음"으로 답할 수 있습니다. 광고·분석 SDK를 넣으면 그 SDK가 수집하는 항목을 반드시 반영합니다.
3. **광고**: 광고 포함 여부를 선언합니다(MVP: 없음).
4. **콘텐츠 등급(IARC)** 설문: 폭력·도박 요소 없음 → 전체이용가 예상.
5. **타겟층**: 만 13세 미만을 포함하면 가족 정책(Families)이 적용되어 광고 SDK 제한이 생깁니다. **"13세 이상"으로 두는 것이 MVP에는 단순합니다.** 아동 대상으로 출시하려면 그때 가족 정책을 검토합니다.
6. 정부 앱, 금융 기능, 건강 앱 등 해당 없는 항목은 "아니요".

## 6단계. 비공개 테스트 (14일)
1. **테스트 → 비공개 테스트**에서 트랙을 만들고 같은 AAB(또는 새 versionCode)를 올립니다.
2. 테스터 12명 이상을 이메일 목록이나 Google 그룹으로 추가하고, 참여 링크를 공유합니다. 테스터는 **링크로 참여를 수락**하고 앱을 설치해야 집계됩니다.
3. 14일 동안 12명 이상이 **계속 참여 상태**를 유지해야 합니다. 중간에 나간 사람은 빠지므로 여유 있게 15~20명을 모으세요.
4. 이 기간에 받은 피드백으로 레벨 난이도를 조정하고 업데이트를 올립니다.

## 7단계. 프로덕션 출시
1. 대시보드의 **프로덕션 액세스 신청**에서 테스트 방법, 받은 피드백, 출시 준비 상태에 대한 질문에 답합니다. 심사에 보통 며칠 걸립니다.
2. 승인 후 **프로덕션 → 새 버전 만들기** → AAB 선택 → 출시 노트 작성 → 국가 선택(처음에는 한국 + 영어권 몇 곳 추천).
3. **단계적 출시** 10% → 이상이 없으면 50% → 100%.
4. 첫 심사는 며칠 걸릴 수 있습니다. 거절되면 사유 메일의 정책 항목을 고쳐 다시 제출합니다.

## 8단계. 출시 후
- Play Console **안드로이드 바이탈**에서 비정상 종료율과 ANR을 매일 확인합니다.
- 리뷰에 답글을 답니다. 레벨별 이탈이 몰린 곳은 03 생성기로 다시 만들어 업데이트합니다.
- 업데이트는 `versionCode`를 올려 같은 절차(내부 테스트 → 프로덕션)로 배포합니다. 개인 계정의 14일 비공개 테스트 조건은 **최초 프로덕션 출시 때 한 번만** 적용됩니다.

## (선택) 자동 배포
- GitHub Actions에서 `./gradlew bundleRelease` 후 Gradle Play Publisher 또는 fastlane `supply`로 내부 테스트 트랙에 자동 업로드할 수 있습니다.
- 업로드 키와 Play API 서비스 계정 JSON은 GitHub Secrets에만 넣습니다.

## 완료 기준
- [ ] 내부 테스트 설치 확인
- [ ] 비공개 테스트 12명 이상 × 14일 완료
- [ ] 프로덕션 승인, 단계적 출시 100% 도달
- [ ] 업로드 키와 비밀번호가 두 곳 이상에 안전하게 백업됨
