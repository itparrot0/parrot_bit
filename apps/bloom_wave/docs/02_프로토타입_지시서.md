# 02. 프로토타입 지시서 — 브라우저에서 규칙 검증하기

## 목표
그래픽 없이 **브라우저에서 실제로 플레이**해 보며 확정 규칙(웨이브 중 탭 허용)이 재미있는지, 틱 속도가 적당한지를 1~2일 안에 판단합니다.

## 입력
- `01_게임기획서.md` 4장 규칙
- `reference/src/engine.ts`, `solver.ts`, `generator.ts`, `arts.ts` (이미 동작·테스트됨)

## 산출물
- `prototype/` 폴더: Vite + TypeScript 웹 앱 1개
- 플레이 테스트 메모 (`prototype/PLAYTEST.md`)

## 사전 준비
- Node.js 22.18 이상 (`node --version`). 참조 구현은 빌드 없이 `node src/cli.ts`로 실행됩니다.
- 참조 구현이 정상인지 확인:
  ```bash
  cd reference
  npm test          # 테스트 9개 통과해야 함
  npm run demo -- mushroom 3 1 2 5 300   # 레벨 하나를 만들고 솔버 해법을 텍스트로 재생
  ```

## 작업 단계
1. **프로젝트 생성**: `npm create vite@latest prototype -- --template vanilla-ts`.
2. **엔진 복사**: `reference/src/{engine,solver,generator,arts}.ts`를 `prototype/src/core/`로 복사합니다. import 경로의 `.ts` 확장자가 Vite에서 문제가 되면 `tsconfig.json`에 `"allowImportingTsExtensions": true, "noEmit": true`를 넣습니다.
3. **보드 렌더링 (Canvas 2D)**: 칸마다 사각형을 그립니다.
   - 씨앗: 색을 30% 밝기로 채우고 가운데 작은 점
   - 발아: 색 60% + 싹 모양(삼각형)
   - 개화: 원래 색 100% + 원(꽃)
   - 빈 칸: 그리지 않음
4. **슬롯·대기열 UI**: 보드 좌우에 슬롯 2칸씩, 아래에 대기열. 각 물방울에 색 원과 양 숫자를 표시합니다. 맨 앞 물방울을 강조합니다.
5. **게임 루프와 입력**: `setInterval`(기본 150ms)로 `isActive(s)`이면 `tick(level, s)`를 호출하고 결과 `TickEvent`를 화면에 반영합니다. 대기열 맨 앞 탭은 틱 사이 언제든 `deploy(level, s)`로 처리합니다(빈 슬롯이 있을 때만). 탭 가능 여부는 `legalActions(s)`로 판단합니다. 맨 앞 물방울과 같은 색 발아 칸은 미리 빛나게 합니다.
6. **웨이브 연출**: 각 `TickEvent`(슬롯별 개화 칸, 새 발아 칸, 비워진 슬롯)를 다음 틱이 오기 전까지 재생합니다. 틱 간격 슬라이더(80~300ms)를 디버그 패널에 둡니다. 재생 중에는 입력을 막습니다. 상태 변경은 즉시 적용하고, 화면만 지연해서 그리는 방식이 가장 간단합니다(그리기 전용 상태 사본 사용).
7. **디버그 패널** (화면 오른쪽):
   - 아트 선택 / 시드 / 시작 지점 수 / 물방울 양 범위 / 순서 흔들기 횟수 / 목표 클리어율 → [생성] 버튼
   - 규칙 옵션: `realtime`(기본 켬), `queuePick`(기본 1) 전환 — 비교 실험용
   - [솔버 힌트]: `solve(level, options)` 결과의 첫 수를 표시
   - [되돌리기]: 수마다 `cloneState` 스냅샷을 스택에 쌓기
   - 지표 표시: 슬롯 최대/평균 점유, 무작위 클리어율, 솔버 노드 수, score
   - [레벨 JSON 복사] 버튼
8. **플레이 테스트**: 아래 표를 채워 `PLAYTEST.md`에 기록합니다.

| 확인 항목 | 틱 150ms | 틱 250ms | 웨이브 후에만 탭 (비교) |
|---|---|---|---|
| 첫 판에서 규칙을 설명 없이 이해했나 | | | |
| 어려운 레벨(score 70 이상)에서 "다시 해보고 싶다"고 느꼈나 | | | |
| 졌을 때 왜 졌는지 알 수 있었나 | | | |
| 한 판 평균 시간 | | | |
| 웨이브 연출이 시원했나 | | | |
| "지금 넣을까 기다릴까"를 실제로 고민했나 | | | |

## 완료 기준
- [ ] 생성 → 플레이 → 클리어/실패 화면까지 끊김 없이 동작
- [ ] 솔버가 "풀린다"고 한 레벨을 사람이 실제로 클리어함 (최소 5개)
- [ ] 기본 틱 속도를 정하고 `00_규칙_확인_질문.md`에 기록
- [ ] 규칙을 바꿨다면 `reference/src/engine.ts`와 테스트를 먼저 고치고 `npm test` 통과
