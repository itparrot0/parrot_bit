## 확정 규칙

| 번호 | 확정 내용 |
|---|---|
| Q1 | **자동 확산(B안)**. 플레이어는 물방울만 탭하고, 같은 색 발아 칸 전체에서 웨이브가 자동으로 퍼짐 |
| Q2 | 물방울은 **발아 칸에만** 소모됨. 씨앗·개화 칸에는 소모되지 않음 |
| Q3 | 색별 씨앗을 물방울로 분할(예: 빨강 12칸 → 3, 5, 4). 물방울은 숫자(양)만큼 개화. 물방울 총량 = 칸 수이므로 **슬롯이 막힐 때만 짐** |
| Q4 | 개화한 칸은 **8방향**의 씨앗을 색과 상관없이 발아시킴. 8방향 순서는 **남동 > 남 > 남서 > 서 > 북서 > 북 > 북동 > 동**을 한 바퀴(링)로 봄. **한 번에 한 링만** 퍼지고, 물방울이 남으면 다음 링을 다시 계산해서 퍼짐 |
| Q5 | ~~대기열 맨 앞 물방울만 탭 가능~~ → **(2026-11-04 변경)** 대기열은 **3줄 이상**이고, **아무 줄이나 그 줄의 맨 앞 물방울**을 탭. 탭한 물방울은 활성 슬롯으로 이동해 슬롯 규칙대로 링을 계산하며 개화 |
| Q6 | 맨 앞 물방울은 **지금 쓸 수 있는지와 상관없이** 탭하면 슬롯으로 이동. 실패 = 활성 슬롯 4칸이 모두 차 있고 그 4개가 모두 쓸 수 없는 상태 |

### 확정 규칙을 코드로 옮기며 정한 세부 사항
아래는 답변에서 직접 다루지 않아 자연스러운 쪽으로 정한 부분입니다. 다르게 원하시면 알려 주세요.

1. **링에 들어가는 칸**: 그 물방울과 같은 색인 발아 칸 전체입니다. 링 안의 개화 순서는 **발아한 순서**를 따릅니다. 한 칸 주변 8칸은 남동부터 시계 방향으로 발아하므로, 양이 링 중간에 바닥나면 이 순서로 앞쪽 칸이 먼저 핍니다.
2. **방금 발아한 칸**: 이번 링에서 발아한 칸은 다음 링부터 개화 대상이 됩니다(한 번에 한 링).
3. **슬롯 여러 개가 동시에 동작할 때**: 한 틱에 슬롯마다 한 링씩, 슬롯 번호 순서(화면에서 왼쪽 → 오른쪽)로 처리합니다. 같은 색 물방울이 둘이면 앞 슬롯이 먼저 가져갑니다.
4. **슬롯에 남은 물방울**: 나중에 다른 물방울이 그 색 씨앗을 발아시키면 **자동으로 다시 퍼집니다**. 그래서 "지금은 못 쓰는" 물방울도 나중에 풀릴 수 있습니다.
5. **탭할 수 있는 때**: 웨이브가 진행 중일 때도 빈 슬롯이 있으면 언제든 탭할 수 있습니다(아래 결정 사항). 탭한 물방울은 다음 틱부터 함께 퍼집니다.
6. **시작 지점**: 전염이 8방향이 되었으므로, 대각선으로만 이어진 픽셀도 같은 덩어리입니다. 생성기는 8방향으로 이어진 덩어리마다 시작 발아 지점을 최소 1개 넣습니다.
7. **슬롯 배치**: 빈 슬롯 중 번호가 가장 작은(가장 왼쪽) 칸부터 채웁니다.

## 결정 사항 (2026-10-28): 웨이브 중에도 탭 허용

웨이브가 멈춘 뒤에만 탭할 수 있으면 플레이어의 행동이 항상 "맨 앞 탭" 하나뿐이라, 결과가 대기열 순서로 정해져 버립니다. 그래서 **웨이브가 퍼지는 도중에도 맨 앞 물방울을 탭할 수 있게** 했습니다. 이제 플레이어의 선택은 **"지금 넣을까, 웨이브가 더 퍼질 때까지 기다릴까"**입니다.

- 너무 일찍 넣으면: 아직 그 색 발아 칸이 없는 물방울이 슬롯을 차지하고, 같은 색 물방울끼리 링을 나눠 가져 양이 애매하게 남습니다.
- 기다리면: 슬롯이 비고 다음 색이 깨어난 뒤에 넣을 수 있지만, 웨이브가 멈추면 어차피 넣어야 합니다.
- 엔진은 "틱"(웨이브 한 링)을 시간 단위로 씁니다. 앱에서는 틱이 일정한 간격(기본 300ms, 2026-11-04 변경)으로 흐르고, 탭은 틱 사이 아무 때나 받습니다.

측정 결과 (그림 3종 × 시드 4개, 무작위로 탭/기다리기를 고르는 봇의 클리어율):

| 그림 | 순서 흔들기 150회 | 1500회 |
|---|---|---|
| tulip (31칸) | 100% | 100% |
| mushroom (66칸) | 11~100% | 7~73% |
| sunflower (81칸) | 13~100% | 10~100% |

- 칸이 적고 색이 3개 이하인 그림은 어렵게 만들기 어렵습니다. 튜토리얼 구간에 씁니다.
- 같은 그림이라도 시드에 따라 쉬운 배치에 갇히는 경우가 있습니다. 생성기는 그림마다 시드를 여러 개 돌려 목표 난이도에 가장 가까운 것을 고릅니다.
- 비교용으로 "웨이브가 멈춘 뒤에만 탭"(`TURN_BASED`), "대기열 앞 N개 중 선택"(`queuePick`)을 엔진 옵션으로 두었으나, 2026-11-04에 대기열 여러 줄(`lanes`)로 대체되었습니다.

## 결정 사항 (2026-11-04): APK 플레이 피드백 반영

| 항목 | 결정 |
|---|---|
| 대기열 줄 수 | 한 줄 대기열은 순서대로 탭만 하면 깨지므로 금지. **모든 레벨 3줄 이상**(상급 일부 4줄). 플레이어는 아무 줄의 맨 앞을 탭 |
| 미리 보이는 물방울 수 | 레벨 옵션 `options.visible`(줄마다 맨 앞 포함 몇 개 보이나). **2차 피드백으로 모든 레벨 3 = 탭할 1개 + 다음 2개**(조금은 예측할 수 있게). 나머지는 `+N` 숫자로만 표시. 규칙(클리어 가능 여부)에는 영향 없음 |
| 그림 해상도 | 같은 그림을 2배로 키운 버전(`meta.scale` 2)으로 칸 수를 늘려 Hard화 |
| 난이도 등급 | 생성기가 무작위 클리어율로 `meta.difficulty`를 매김: 30% 이상 normal, 15~30% hard, 8~15% superHard, 8% 미만 megaHard |
| 난이도 경고 | hard / superHard / megaHard 스테이지는 시작 전에 **Hard / Super Hard / Mega Hard** 경고창을 띄우고, 확인을 누르면 시작 |
| 별점 | **폐지**. 완성 여부만 기록하고, 완성 시 Full Bloom 연출 + "완성!" 후 다음 스테이지로 유도 |
| 광고 | 스테이지 **완성 후** 완성 화면을 떠날 때 전면 광고 1회. **실패 시 광고 없음**. "광고 제거" 구매 시 건너뜀 |
| 틱 속도 | 기본 150ms → **300ms**, 느리게 450ms. 개화·물줄기 연출도 약 2배 느리게 |
| "대기" 표시 | 삭제 (못 쓰는 물방울을 따로 표시하지 않음). 맨 앞 색 발아 칸 하이라이트도 줄이 여러 개라 삭제 |
| 화면 배치 | 보드는 위쪽에 가로 최대 1000(논리 1080 기준), 활성 슬롯 4칸은 보드 **아래** 한 줄(보드와 겹치지 않음), 그 아래 대기열 세로 줄들, 맨 아래 버튼 |
