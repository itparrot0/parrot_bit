# proto_full_bloom (만개 — 프로토타입)

색상 연쇄 개화 퍼즐 프로토타입.

- 기획: [`docs/prd/full_bloom.md`](../../docs/prd/full_bloom.md)
- **기본값은 폐기다.** 승격 시 `apps/full_bloom`을 새로 만들고 검증된 코드만
  이식한 뒤 이 디렉터리를 지운다 (`docs/03-architecture.md` §6).

## 검증할 것 (PRD §9)

1. **한 수의 결과를 미리 예측할 수 있는가.** 못 하면 퍼즐이 아니라 도박이다.
2. **슬롯이 막히는 답답함이 긴장으로 느껴지는가, 그냥 짜증인가.**
3. **다 피었을 때 만족스러운가.**

재미가 안 나오면 PRD §9.1의 레버를 순서대로 당긴다 (슬롯 수 ↓ → 큰 물뿌리개
비중 ↑ → 클릭 한 번 = 물 한 번 → 시작 지점 선택).

## 현재 상태

규칙·솔버·보드·HUD 전부 동작한다. 테스트 56개.
**레벨 생성기는 아직 없다** — PRD §9.1대로 손으로 만든 레벨로 재미를 먼저 본다.

## 구조

```
lib/
├── domain/              순수 Dart. Flutter/Flame 없이 테스트된다
│   ├── cell_pos.dart        좌표 + 이웃 순서(하→좌→우→상)
│   ├── bloom_color.dart     색
│   ├── cell.dart            칸의 3단계 (씨앗·꽃송이·개화)
│   ├── watering_can.dart    물뿌리개 (남은 횟수를 들고 있다)
│   ├── bloom_level.dart     레벨 정의 + §3.7 불변식 검사
│   ├── bloom_board.dart     큐·개화 전파·색 매칭·슬롯·승패·되돌리기
│   └── bloom_solver.dart    교착 없이 끝까지 가는지 탐색 + 난이도 지표
├── levels/handmade_levels.dart   손으로 만든 레벨 4개
├── game/                Flame — 모델 결과를 그리기만 한다
└── main.dart            HUD (슬롯·대기열·되돌리기·레벨 선택)
```

**규칙은 `lib/domain/`에만 있고, 솔버도 같은 모델을 쓴다.** 규칙이 바뀌면 솔버가
자동으로 따라간다 — 규칙을 두 번 구현하지 않는다 (PRD §10).

## 화면에서 읽는 법

- **씨앗** 작고 어두운 점 / **꽃송이** 중간 원 + 흰 테두리 / **개화** 큰 원
- **꽃송이 위의 숫자가 큐 순번이다.** 이게 "큐를 화면에 보여주기"(PRD §5-3)의
  실현이고, 예측 가능성이 전부 여기서 나온다.
- 슬롯을 **누르고 있으면** 그 색이 다음에 피울 칸이 흰 사각으로 집힌다.
- `쓸 곳 없음` 슬롯은 큐에 그 색이 없다는 뜻이다 (눌러도 안 나간다).

## 레벨 추가하기

`lib/levels/handmade_levels.dart`에 더한다. **§3.7 불변식은 생성자가 검사하므로**
색깔별 물 횟수가 칸 수와 어긋나면 그 자리에서 던진다 — 플레이 중에 발견할 일이
없다. 테스트가 모든 레벨을 솔버로 풀어보므로, 안 풀리는 레벨을 넣으면 실패한다.

## 실행

```sh
flutter pub get                            # 저장소 루트에서 1회
cd apps/proto_full_bloom && flutter run
flutter test                               # 이 앱만
```

## 알려진 미완

- 레벨 생성기 없음 (PRD §4 — 재미 검증 후에 만든다)
- 연쇄 연출은 지연 펄스뿐. PRD §6대로 "읽히는 수준"까지만
- 플랫폼은 Android·iOS만 생성
