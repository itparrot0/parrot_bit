# proto_garden_grow (Garden Grow — 프로토타입)

색상 연쇄 개화 퍼즐 프로토타입. **Full Bloom은 게임 이름이 아니라 클리어 연출
이름**이다 (기획서 §10).

> **디렉터리 리네임 보류.** 패키지·디렉터리는 아직 `proto_full_bloom`이다 —
> IntelliJ 분석기가 디렉터리를 잡고 있어 `git mv`가 실패했다. IDE에서 프로젝트를
> 닫고 `git mv apps/proto_full_bloom apps/proto_garden_grow` 후 pubspec 이름·
> import·Android namespace를 함께 고친다 (PRD §12).

- 기획: [`docs/prd/garden_grow.md`](../../docs/prd/garden_grow.md) (규칙 최종본),
  상위 기획서 Garden Grow v0.1
- **기본값은 폐기다.** 승격 시 `apps/garden_grow`를 새로 만들고 검증된 코드만
  이식한 뒤 이 디렉터리를 지운다 (`docs/03-architecture.md` §6).

## 조작 구조 (2026-10-10 확정)

- **레인 여러 기둥(세로)** — 맨 위만 꺼낼 수 있다. **기본은 전부 공개**
  (모든 레인의 색·개수가 보인다). 레벨이 숨김 표시한 물뿌리개만 맨 앞에 올
  때까지 `?` 덮개로 가려진다 — 난이도 요소. 묻힌 물뿌리개를 꺼내려면 앞을
  먼저 써야 한다 (기획서 §8 자유 선택 + Colony Flow의 줄 세우기).
- **활성화 슬롯 (기본 4개)** — 꺼낸 물뿌리개가 재생되는 자리. 대상이 없어
  멈추면 **남은 횟수를 든 채 주차**되고, 소진돼야 비워진다. 대상이 없는 색도
  꺼낼 수 있다 — 주차를 감수하고 레인을 파내는 수가 된다.
- **자동 재개** — 개화로 주차가 쓸 수 있게 되면 같은 수 안에서 즉시 이어서
  재생된다(연쇄). 플레이어의 결정은 "레인에서 무엇을 꺼내는가" 하나다.
- **고착 재정렬** — 물뿌리개가 멈출 때마다 큐가 바깥 고리 우선으로 재정렬돼,
  다음 수는 꽃무리 가장자리에서 이어진다.
- **레인 공개 범위 (기본 앞 2개)** — 뒤는 +N으로만 보인다. 난이도 다이얼.
- 지는 길은 **교착**(둘 수 있는 수가 없음) 하나뿐이다 — 색깔별 물 횟수 =
  칸 수 덕에 물이 모자라 지는 일은 없다.

## 검증할 것

1. **한 수의 결과를 미리 예측할 수 있는가.** 못 하면 퍼즐이 아니라 도박이다.
2. **주차가 슬롯을 막는 답답함과 레인 파내기가 긴장으로 느껴지는가, 짜증인가.**
3. **다 피었을 때 만족스러운가.**

## 현재 상태

규칙·솔버·보드·HUD·랜덤 생성기 전부 동작한다.

생성기는 **그림 먼저, 레인은 그 다음** 두 단계다:

1. `drawPicture(seed, colorCount)` — 실루엣(하트·꽃·나비·다이아몬드) 위에
   색을 칠해 **그림**을 만든다. 색 수가 난이도의 1차 다이얼(기획서 §13).
   `renderPicture`/`parsePicture`로 텍스트(R/B/Y/G/P 도트아트)와 왕복되므로,
   프로그램이 그린 그림을 저장해 다듬거나 **사람이 색까지 직접 그릴 수 있다.**
2. `generateFromPicture(seed, picture)` — 그림은 고정하고 시작 지점·물뿌리개
   분할·레인만 생성해 솔버로 검증한다. **그림 하나 × 레인 시드 = 무한 레벨.**

`generateAtDifficulty(seed, BloomDifficulty.easy~expert)`가 색 수·물뿌리개
크기·슬롯 수를 프리셋으로 묶는다. HUD의 **랜덤** 버튼은 normal 기본값으로
돌고, 이름의 `#시드`로 같은 레벨을 재현할 수 있다. 역생성(기획서 §14의
"연쇄를 먼저 설계")은 이후 단계.

## 구조

```
lib/
├── domain/              순수 Dart. Flutter/Flame 없이 테스트된다
│   ├── cell_pos.dart        좌표 + 이웃 순서(하→좌→우→상)
│   ├── bloom_color.dart     색
│   ├── cell.dart            칸의 3단계 (씨앗·발아·개화)
│   ├── watering_can.dart    물뿌리개 (남은 횟수를 들고 있다)
│   ├── bloom_level.dart     레벨 정의(레인·슬롯 수·공개 범위) + 정확 일치 검사
│   ├── bloom_board.dart     큐·고리·개화 전파·레인·활성화 슬롯·승패·되돌리기
│   ├── bloom_solver.dart    교착 없이 끝까지 가는지 탐색 + 난이도 지표
│   └── bloom_generator.dart 그림 그리기 + 레인 생성 (역산·솔버 검증·난이도 프리셋)
├── levels/handmade_levels.dart   손으로 만든 레벨 4개
├── game/                Flame — 모델 결과를 그리기만 한다
└── main.dart            HUD (활성화 슬롯·레인·되돌리기·레벨 선택)
```

**규칙은 `lib/domain/`에만 있고, 솔버도 같은 모델을 쓴다.** 규칙이 바뀌면 솔버가
자동으로 따라간다 — 규칙을 두 번 구현하지 않는다 (PRD §10).

## 화면에서 읽는 법

- **씨앗** 작고 어두운 점 / **발아** 중간 원 + 흰 테두리 / **개화** 큰 원
- **레인 앞이나 주차된 물뿌리개를 누르고 있으면** 그것이 피울 칸에
  `1, 2, 3…`이 찍힌다. 남은 횟수만큼만 붙으므로 "이 한 수가 어디까지 가나"가
  그대로 보인다. 누르지 않으면 번호를 안 띄운다.
- 연쇄는 **개화된 순서 그대로** 한 칸씩 터진다 — 자동 재개로 이어진
  물뿌리개들까지 한 줄로 흐른다.
- 활성화 슬롯의 `주차` 표시는 큐에 그 색이 없다는 뜻이다 — 그 색 발아가
  생기면 탭해서 재개한다.

## 레벨 추가하기

`lib/levels/handmade_levels.dart`에 더한다. **정확 일치 불변식은 생성자가 검사하므로**
색깔별 물 횟수가 칸 수와 어긋나면 그 자리에서 던진다 — 플레이 중에 발견할 일이
없다. 테스트가 모든 레벨을 솔버로 풀어보므로, 안 풀리는 레벨을 넣으면 실패한다.

```sh
cd apps/proto_full_bloom && flutter run

```
