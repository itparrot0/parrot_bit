## 0. Garden Grow — 프로토타입 동작, 기획서 v0.1로 문서 교체

| | |
|---|---|
| 코드 | `apps/proto_full_bloom` (동작함, 테스트 94개) — **디렉터리 리네임 보류** (IDE 락) |
| 문서 | `docs/prd/garden_grow.md` = **기획서 Garden Grow v0.1 원문 그대로** (2026-10-10 교체) |

색상 연쇄 개화 퍼즐. 씨앗 🌱 → 발아 🌿 → 개화 🌸 3단계로, 색상별 물뿌리개를
쓰는 순서가 퍼즐이 된다. Full Bloom은 클리어 연출 이름이다.

**문서 이력 주의**: 이전 PRD(규칙 개정 3차까지)는 기획자의 요청으로 **기획서
v0.1 원문으로 전면 교체**됐다. 이전 PRD에만 있던 결정들 — 활성화 슬롯/대기열
구조, 색깔별 물 횟수 = 칸 수(정확 일치), 시작 지점 = 발아, FIFO 큐(원형 확장),
교착 = 유일한 패배 — 은 **문서에는 더 이상 없지만 코드에는 구현돼 있다.**
근거가 필요하면 git 로그(befc4ed~5d97dbf)의 커밋 메시지를 본다.

**선택 구조 확정 (2026-10-11)**: 단일 대기열+슬롯을 버리고 **레인 구조**로
교체했다. 레인 여러 줄(맨 앞만 꺼낼 수 있음) + 활성화 슬롯
(기본 4개, 2026-10-11 변경; 꺼낸 물뿌리개가 재생되는 자리, 멈추면 남은 횟수를 든 채 주차, 소진돼야
비워짐). 대상 없는 색도 꺼낼 수 있다 — 주차를 감수하고 레인을 파내는 수.
교착 = 둘 수 있는 수가 없음(재개 불가 + 빈 슬롯 없음/레인 소진).
기획서 §8의 자유 선택과 §9의 Colony Flow식 줄 세우기를 이것으로 잇는다.

**개화 순서 확정 (2026-10-11)**: 재생 중에는 FIFO(안쪽 고리 → 바깥 고리),
**물뿌리개가 멈추면(고착) 큐를 바깥 고리 우선으로 재정렬**한다 — 다음 수는
꽃무리 가장자리에서 이어진다. 같은 고리 안에서는 발아 순서 유지(안정 정렬).
참고: "개화된 꽃무리를 개화 순서로 훑는 재계산"은 기존 FIFO 큐와 항상
동일함을 확인했고, 그래서 재계산의 실질을 바깥-우선 정렬로 정의했다.

**자동 재개 확정 (2026-10-11)**: 개화로 주차된 물뿌리개가 쓸 수 있게 되면
**같은 수 안에서 즉시 자동 재개**한다 (슬롯 번호 순, 연쇄, 고정점까지).
결과: 수가 끝나면 대상 있는 주차가 남지 않으므로 **플레이어의 결정은 "레인에서
무엇을 꺼내는가" 하나로 모인다** — 수동 재개 탭이 사라졌다 (기획서 원칙 1:
선택은 단순하게, 결과는 깊게). 솔버 분기도 레인 수 이하로 줄었다.

여전히 열린 것: §19(횟수 +1)·§20(무지개 물뿌리개)는 정확 일치 불변식과 양립하지
않는다 — 아이템을 넣으려면 검사 완화 또는 "교착 해소형" 아이템으로 재설계.

**끝난 것**: 순수 Dart 규칙 모델 + 솔버 + Flame 보드 + HUD + 손 레벨 4개.
레인 앞/주차된 것을 누르면 그 물뿌리개가 피울 칸에 1..N이 찍힌다(남은
횟수만큼만). 연쇄 연출은 개화된 순서 그대로 한 칸씩 터진다(자동 재개 포함).

**규칙 확정 선언 (2026-10-11)**: 레인 + 활성화 슬롯 + 디깅 + 바깥-우선
재정렬 + 자동 재개 — 이 조합을 프로토타입의 규칙으로 확정했다. HUD 레인은
세로 기둥이다(맨 위만 꺼냄).

**레인 공개 (2026-10-11 변경)**: 기본은 **전부 공개**(모든 레인의 색·개수).
숨김은 물뿌리개 단위의 레벨 요소(`hiddenCans`)로, 표시된 것만 맨 앞에 올
때까지 ? 덮개로 가려진다. "맨 앞에 올 때 드러나는" 류의 다른 요소도 나중에
이 자리에 같은 방식으로 붙는다. laneRevealCount(개수 기반 가림)는 제거.

**다음 할 일**:
1. 코드 ↔ 기획서 §43 미확정 항목의 기준 정리 (위 문단).
2. 직접 플레이해서 재미 판정 — 기획서 §44 Phase 1~2가 사실상 끝나 있다.
3. ~~레벨 생성기~~ ✔ `BloomGenerator` — **그림 먼저, 레인은 그 다음** 2단계
   (2026-10-11 재구성). `drawPicture`(실루엣 4종 + 색 수 = 난이도)가 그림을
   만들고, `generateFromPicture`가 그림을 고정한 채 시작 지점·분할·레인만
   생성해 솔버로 검증한다 — **그림 하나 × 레인 시드 = 무한 레벨**. 그림은
   R/B/Y/G/P 도트아트 텍스트와 왕복(render/parse)되므로 사람이 색까지 직접
   그릴 수 있다. `BloomDifficulty` easy~expert 프리셋(색 수·물뿌리개 크기·
   슬롯 수). 연결 안 된 그림은 입구에서 거부. HUD "랜덤" 버튼은 normal.
   남은 것: 기획서 §14 역생성(연쇄 먼저 설계) + Solution Count 등 지표 확장.
4. 디렉터리 리네임: IDE 닫고 `git mv apps/proto_full_bloom apps/proto_garden_grow`
   → pubspec 이름·import·Android namespace 수정.

## 저장소 공통 메모

- **`melos run format`은 검사만 하지 않고 파일을 덮어쓴다.** `dart format
  --set-exit-if-changed .`가 파일을 재작성한 뒤 exit 1을 낸다. CI에서는 작업
  트리를 버리니 검사처럼 동작하지만, 로컬에서 돌리면 재포맷이 남는다.
  저장소는 `d51467d`에서 한 번 전체 정렬했다.
- **CI 워크플로가 없다.** `docs/03-architecture.md` §1은 CI가
  `melos run analyze && melos run test`만 돌리면 되게 유지한다고 전제하는데,
  `.github/`가 아직 없다.
- `apps/proto_merge`에는 `flutter create`가 만든 `analysis_options.yaml`이
  남아 있다. 루트 것과 내용이 같아 `apps/sleep_log`에서는 지웠다.
