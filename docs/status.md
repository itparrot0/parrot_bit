**스토어 상품 등록·가격·실기기 결제는 아직** — 스토어 연결이 없으면 구매는 실패로 끝나고 게임은 그대로다.
알려진 한계: 결제가 "대기(pending)"로 끝나 나중에 승인되면 그 자리에서 지급되지 않는다 — 구매 복원으로 받는다
(Bloom Wave 와 같음).

**지대 보너스 표시 (2026-11-05)**: 드래그 중 보너스 지대 칸 밝히기(산출원·최고 레벨 바로 아래 아이템),
자기 지대 산출원에 "×1.5". 이때 산출원의 "+N" 쌓인 양 라벨이 스킨에 가려 안 보이던 버그도 고쳤다
(라벨 priority).

**첫 실행 안내 (2026-11-05)**: 손가락 두 번 — 생성기 탭, 첫 확장(가장 싼 잠긴 칸). 규칙은 `lib/economy/hints.dart`,
저장의 `hints` 칸(없는 옛 저장은 보드로 짐작해 이미 놀던 사람에게는 안 띄운다).

**한 칸씩 확장 (2026-11-05, 사용자 결정)**: 행/열 통째(넓히기·파기 손잡이)를 버리고, 열린 칸과 맞닿은
잠긴 칸 하나를 골라 연다. 최대 보드·지대 배치는 그대로(6열 × 숲 4 + 동굴 3). 비용은 지대별 n번째 칸 값
(`theme.dart`의 `forestCellCosts`·`caveCellCosts`). 첫 동굴 칸 = 동굴 진입, 그 칸에 자갈 생성기.
저장은 열린 칸 목록(`unlocked`) — 이전 저장(`columns`·`caveRows`)은 직사각형으로 열어 읽는다.
테마 문서 §5·§7-1·§8, 화면 흐름 §3.2를 고쳤다.

**경제 시뮬레이션 (2026-11-05)**: `tool/economy_sim.dart` — 결과·결론은 `docs/design/deep_grove-economy-sim.md`.
찾은 것 셋: (1) **창고가 거의 차면 산출이 영구히 멈추는 버그** — 고침(빈 공간을 정수 단위로 나눔).
(2) **지금 수치는 너무 빠르다** — 첫 테마가 계속 플레이 18분, 생성기 무한 탭 때문에 비용만으로는
조절이 안 된다. (3) **보드 막힘이 실제로 생긴다** — 숲을 목재 산출원으로 채우면 광석이 필요해질 때
돌 키울 칸이 없어 영원히 진행 불가. 해소 장치·첫 테마 목표 길이·속도 손잡이(에너지 등)를 정해야 한다.

**버리기 칸 (2026-11-05)**: 보드 막힘 해소 장치. 보드 아래 칸에 놓으면 버린다 — 자원 환급 없음, 생성기 제외,
산출원은 확인 창. 시뮬레이터에서 막히던 수치(산출 120초)가 낮은 아이템 2~4개만 버리고 모두 완주.

**확인 시트 생략 (2026-11-05)**: 자원이 충분한 잠긴 칸은 탭 한 번에 바로 열린다. 모자랄 때와 테마 완주만 시트.

**다음 할 일**: 첫 테마 목표 길이·속도 손잡이(에너지 등) 결정 → 시뮬레이터로 수치 맞추기. 그 밖에 실제 그래픽(`lib/game/skins/skin_registry.dart`), 실기기 광고·결제 확인, 그리고

## 2. 슬립로그 — v1 기능 전부 동작, 실기기 확인·출시 준비 단계

**끝난 것**: 스캐폴딩 → 도메인 → 달력 위젯 → 저장 계층 → 기록 화면(entry) → 온보딩 → 리포트 → 설정 → 안전 배너 → 생각 돌아보기 → 기간 돌아보기 → **생활 태그·개운함·잠든 시각·전화 연결·백업**. 테스트 268개 통과.

- `lib/domain/` — 수면시간 계산(자정 넘김), z 4단계 판정, 감정 태그 팔레트,
  안전 안내 2단계 판정, 태그별 수면 집계. 순수 Dart.
- `lib/widgets/calendar/` — 월간 달력. 패키지를 쓰지 않고 직접 만들었다.
- `lib/data/` (2026-11-05) — 저장소에서 drift를 처음 쓴다 (PRD §9-3).
  - `database.dart`: 표 2개. `diary_entries`(날짜 ISO 문자열 키, 취침·기상 분) +
    `entry_tags`(날짜, 태그 id). 태그 표는 외래 키 CASCADE로 기록과 함께 지워진다.
    `database.g.dart`는 생성 파일이지만 커밋한다 — 앱을 돌리는 데 build_runner가
    필요 없게. 스키마를 바꾸면 `dart run build_runner build` 후 함께 커밋한다.
  - `diary_repository.dart`(인터페이스) + `drift_diary_repository.dart`(구현):
    `watchAll`(전체, 날짜순 스트림) / `find` / `save`
    (같은 날 덮어쓰기, 빈 기록이면 삭제) / `delete` / `deleteAll`. 모르는 태그 id·
    깨진 행은 건너뛴다. 인터페이스로 나눈 이유: drift 쿼리는 위젯 테스트의 가짜
    시간 안에서 끝나지 않는다 — 화면 테스트는 `test/support/`의 메모리 구현을 쓰고,
    drift 구현은 `test/data/`가 실제 SQLite(메모리)로 검증한다.
  - `settings_repository.dart`: 목표 수면시간을 `core_storage`에. 설정 전이면
    null — 온보딩 판단에 쓰려고 기본값과 구분한다.
  - `providers.dart`: DB·저장소·오늘 날짜·전체 기록·목표 Provider. 목표는
    `main`이 `runApp` 전에 한 번 읽어 `initialSleepTargetProvider`로 넣고,
    `savedSleepTargetProvider`(null = 아직 안 정함)가 들고 있다. 바꿀 때는
    `.notifier.set(target)` — 저장과 동시에 달력·기록 화면의 z가 다시 계산된다.
- 달력 화면이 실제 기록을 그린다. "오늘 기록" 버튼은 오늘 기록이 없을 때만,
  넘길 수 있는 범위는 가장 오래된 기록의 달까지(최소 지난달).
- `entry` 화면 (2026-11-05): "수면 시각 넣기"를 누르면 가장 최근 수면 시각(없으면
  23:00→07:00)으로 채워지고, 시각을 누르면 시간 선택기. 수면시간과 z 단계를 입력
  즉시 표시. 태그는 묶음별 칩, 묶음 안에서 최근 쓴 태그가 앞(`domain/tag_order.dart`,
  화면이 열릴 때 한 번 정해 고르는 중에 움직이지 않는다). 수면만·태그만 저장 가능,
  둘 다 없으면 저장 버튼이 꺼진다. 기록된 날은 편집 모드 + 삭제(확인). 저장 안 하고
  뒤로 가면 버릴지 묻는다. 미래 날짜는 안내만 보여 준다.
- `onboarding` (2026-11-05): 목표 수면시간을 30분 단위로(4~12시간, 기본 7시간)
  고르고, 그 목표로 z 네 단계가 몇 시간부터인지 범례로 바로 보여 준다(경계는
  `SleepTarget.bounds` — 판정과 같은 상수). 라우터 redirect: 목표가 없으면 어디로
  가든 온보딩, 정한 뒤에는 온보딩으로 돌아갈 수 없다.
- `report` (2026-11-05): 달력 앱바의 리포트 버튼으로 진입. 수면을 기록한 날이
  14일 미만이면 "N일 더 기록하면 보여 드려요"와 진행 막대만. 이후 전체 평균을
  기준선으로, 태그별 평균 수면을 짧은 순으로 나열(태그마다 일수 표시). 인과로
  읽히지 않게 "나란히 놓았을 뿐, 원인을 뜻하지는 않아요" 문구를 둔다.
- `settings` (2026-11-05): 달력 앱바의 설정 버튼으로 진입.
  - 목표 수면시간 — 대화상자에서 −/+로 바꾸고, "지난 기록의 z도 다시 계산돼요"를
    저장 전에 알린다. −/+ 조절기와 z 범례는 온보딩과 같은 위젯
    (`widgets/sleep_target_picker.dart`).
  - 마음 돌봄 안내(안전 배너) on/off — 기본 켜짐, `core_storage`에 저장
    (`safetyNoticeEnabledProvider`).
  - 모든 기록 지우기 — 확인 후 `deleteAll`. 목표 같은 설정은 남긴다.
  - 리마인더 알림·데이터 내보내기는 PRD상 Could라 넣지 않았다(동작 안 하는 항목을
    미리 두지 않는다).

- 안전 배너 (2026-11-05, PRD §9-2): 달력 맨 위, 닫을 수 있는 카드(경고색 없음).
  - 판정은 `SafetyCheck`, 노출 규칙은 `domain/safety_notice_policy.dart`: 같은
    단계는 14일 재노출 금지, 2단계를 띄운 뒤 14일은 1단계도 금지. **1단계를 띄운
    뒤라도 2단계는 띄운다** — 더 무거워진 신호를 1단계의 쉬는 기간이 가리면 안 된다
    (PRD에 명시되지 않은 부분이라 이렇게 정했다).
  - `safetyBannerProvider`가 **앱을 열 때 한 번** 정한다 — 기록 저장 직후에 반응하지
    않게 기록 목록을 watch하지 않는다. 띄우기로 정한 날을 단계별로 `core_storage`에
    저장한다(닫든 말든 14일 시작). 설정에서 끄면 즉시 사라진다.
  - 문구는 `widgets/safety_banner.dart`. 2단계는 자살예방상담전화 109,
    정신건강위기상담전화 1577-0199(2026-11 유효 확인, 출시 전 재확인). 번호는 글자로만
    보여 준다 — 눌러서 전화 걸기는 url_launcher가 필요해 넣지 않았다.

- 생각 돌아보기 (2026-11-05, PRD §3-3): 오전·오후 자기 관찰 체크인 + 로컬 알림.
  기본 꺼짐, 설정에서 켜고 시각을 고른다. 묻지 않고 권하는 문구.
  - 도메인 `domain/thought_check_in.dart`, 저장 `thought_check_ins` 표(**DB schema 2**,
    `onUpgrade`에서 표 추가 — schema 1 DB에서 여는 테스트 있음).
  - 화면 `check_in`(`/check-in/:date/:slot`), 달력에 지금 시간대 버튼(켰을 때만).
  - 알림 `data/check_in_reminder.dart`(flutter_local_notifications, 매일·부정확 예약 —
    정확한 알람 권한 불필요). 앱 시작마다 다시 잡고, 누르면 오늘 그 시간대로 간다.
    Android: 부팅 receiver·예약 receiver·core library desugaring 추가.
    iOS: `AppDelegate.swift`에 알림 센터 delegate 지정(플러그인 README의 General setup).
  - 리포트에 "머릿속 속도별 그날의 수면시간"(7일 이상일 때).
  - 안전: 7일 중 3일 감각 "여러 번" → 2단계 배너(`SafetyAdvice.senseSupport`, 수면 기반
    2단계와 쉬는 기간 공유).
  - 앱 표시 이름을 PRD §10대로 `슬립로그`로 바꿨다(AndroidManifest label).

- 기간 돌아보기 (2026-11-05, PRD §3-4): 리포트 앱바 → `review` 화면.
  분석은 `domain/period_review.dart`(3일 이상 연속 흐름, 겹침 흐름, 같은 구간 묶기),
  편지 100문장은 `domain/developer_letters.dart`. 무작위는 `randomProvider`(테스트는 시드 고정).
  앱 전체를 한국어 로케일로 설정했다(`flutter_localizations`) — 날짜·시간 선택기가 한국어로 뜬다.

- 생활 태그 7개·개운함 3단계 (PRD §3-1): **DB schema 3**(`diary_entries.rested`,
  `addColumn` — schema 2 DB에서 여는 테스트 있음). 리포트에 생활·잠든 시각·개운함 대조,
  기간 돌아보기에 "충분히 잤는데 덜 풀림"·"잠든 시각 크게 오르내림" 흐름 (PRD §3-5).

- 상담 번호 전화 연결: `data/phone_dialer.dart`(url_launcher `tel:` — 번호가 채워진 전화

로컬에서 `flutter run`으로 DB 파일이 열리고 기록이 남는지 확인 필요.

**다음 할 일** (권하는 순서):

## 저장소 공통 메모

- **`melos run format`은 검사만 하지 않고 파일을 덮어쓴다.** `dart format
  --set-exit-if-changed .`가 파일을 재작성한 뒤 exit 1을 낸다. CI에서는 작업
  트리를 버리니 검사처럼 동작하지만, 로컬에서 돌리면 재포맷이 남는다.
  저장소는 `d51467d`에서 한 번 전체 정렬했다.
- **CI 워크플로가 없다.** `docs/03-architecture.md` §1은 CI가
  `melos run analyze && melos run test`만 돌리면 되게 유지한다고 전제하는데,
  `.github/`가 아직 없다.
