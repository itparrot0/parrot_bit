# PRD — deep_grove (Deep Grove)

> 머지로 숲을 키우고, 보드를 넓히고, 땅 아래 동굴로 파고드는 머지 게임.
> `apps/proto_merge` 승격작 (판정 기록: `docs/prd/proto_merge.md`).

- **문서 상태**: 초안
- **작성일**: 2026-11-05
- **대상 앱**: `apps/deep_grove` (릴리즈 앱 — 게임 경로, `docs/03-architecture.md` §6)
- **게임 규칙·컨텐츠**: `docs/design/deep_grove-themes.md` (이 PRD는 그 규칙을 되풀이하지 않는다)

## 1. 앱 목적

짧은 틈에 몇 번 머지하고 나가도 **보드가 조금씩 넓어지는 것이 눈에 보이는** 머지 게임.
프로토타입에서 검증한 드래그드롭 머지 조작 위에, 프로토타입에 없던 "왜 계속 머지하는가"의
답 — **다 키운 조각이 자원을 내고, 그 자원으로 보드를 넓힌다** — 을 얹는다. 칸이 모자라서
넓히고, 넓혀서 더 키우는 공간 압박 루프가 이 게임의 전부다.

## 2. 타깃 사용자

- **주 사용자**: 머지 장르를 해 봤거나 처음인 캐주얼 플레이어. 한 손 세로 화면.
- **사용 상황(언제/어디서)**: 하루 여러 번, 한 번에 2~5분. 이동·대기 중 틈새 시간.
  - 접속 동기 둘 — (1) 방치 산출로 창고에 쌓인 자원 회수, (2) 다음 확장까지 남은 자원 채우기.
  - 창고 용량이 차면 산출이 멈추므로(테마 문서 §7-4) "가득 차기 전에 한 번 들어온다"가
    자연스러운 접속 주기가 된다. 푸시 알림은 v1에 없다(§4).

## 3. 핵심 기능

| # | 기능 | 설명 | 우선순위 |
|---|------|------|----------|
| 1 | 머지 보드 | 드래그드롭 판정 4종(머지/이동/자리 교체/스냅백), 생성기 탭 스폰, 생성기끼리 머지. 프로토타입 조작 그대로 | Must |
| 2 | 산출원과 창고 | 체인 최고 레벨 조각은 소멸하지 않고 산출원이 된다. 탭·방치로 창고에 자원이 쌓이고, 창고 용량에서 멈춘다 | Must |
| 3 | 보드 확장 | 자원을 써서 행/열 단위로 넓힌다. 가로 = 숲, 아래 = 동굴. 첫 하향 확장이 동굴 진입이고 자갈 생성기를 준다 | Must |
| 4 | 저장·오프라인 진행 | 보드·창고·확장 상태를 저장한다. 앱을 다시 열면 그 사이 방치 산출을 한 번에 반영한다 | Must |
| 5 | 지대 보너스 | 산출원이 자기 체인과 맞는 지대(거목 → 숲, 광석바위 → 동굴)에 있으면 산출량이 늘어난다 | Should |

v1 컨텐츠 = **첫 테마 하나**(동굴이 있는 숲: 나무·돌 체인 각 5레벨). 테마 완주 시점에
"다음 테마 준비 중"을 보여 준다. 다음 테마는 첫 테마 플레이 데이터를 보고 정한다
(테마 문서 §7-5).

## 4. 명시적 비범위 (Out of Scope)

- **2차 가공·제작대, 세 번째 체인** — 첫 테마는 2체인으로 충분한지 먼저 본다 (테마 문서 §6).
- **다른 종류 조각끼리의 머지** — 조건 불일치는 언제나 자리 교체다. 검증된 예측 가능성을 깨지 않는다.
- **칸을 골라 스폰하는 구조** — 기각 (테마 문서 §7-6). 다음 테마에서 다시 꺼낼 수 있다.
- **유료 재화, 배너·전면 광고** — 수익은 §6의 두 가지만.
- **도감, 장식·꾸미기, 주문·손님 요청, 퀘스트**.
- **서버, 계정, 클라우드 저장, 랭킹** — 전부 로컬.
- **푸시 알림** ("창고가 가득 찼어요") — 재접속 지표(§7)를 보고 v1.x에서 판단.
- **튜토리얼 화면** — 시작 보드(씨앗 생성기 + 씨앗 2개)가 첫 머지를 바로 겪게 한다.
  첫 생성기 탭·첫 확장 버튼에 안내 표시 정도만 둔다.

## 6. 수익 모델

- **유형**: **보상형 광고 + 비소모성 IAP.** 유료 재화 없음, 배너·전면 광고 없음.
- **원칙 — 결제와 광고는 시간을 줄일 뿐 진행을 대신하지 않는다.** 보드 확장은 자원으로만
  열린다. 확장을 돈으로 바로 사는 상품은 두지 않는다 — 확장이 이 게임의 목표 구조라서,
  그걸 팔면 목표가 사라진다.
- **보상형 광고** (플레이어가 버튼을 누를 때만 재생):
  - **복귀 보상 2배** — 앱을 다시 열 때 방치 산출로 쌓인 자원을 2배로 받는다.
  - **산출 가속** — 30분 동안 산출원 산출량 2배. 가속 중에 또 보면 30분 연장. 앱을 닫아도
    남은 가속 시간만큼은 오프라인 산출에도 2배가 걸린다.
  - **하루 6회** (두 지점 합쳐서, 기기 현지 날짜 기준). 첫 값이고 단일 출처는
    `apps/deep_grove/lib/economy/ad_rewards.dart`의 `adRewardConfig`.
  - 광고를 중간에 닫거나 못 받으면 보상 없이 원래 자리로 돌아간다(복귀 보상은 1배로 받는다).
  - 2026-11-05 구현. AdMob 앱·광고 단위는 **Google 테스트 ID** — 출시 전 실제 ID로 교체
    (`lib/platform/ads.dart`, AndroidManifest `APPLICATION_ID`, Info.plist `GADApplicationIdentifier`).
- **비소모성 IAP** (2026-11-05 구현):
  - **창고 확장팩** (`storage_pack`) — 자원별 창고 용량 영구 1.5배(내림). 자원으로 하는 창고
    확장(진행 목표)과 곱해진다: 30/60/120 → 45/90/180.
  - **영구 산출 가속** (`output_boost`) — 산출원 산출량 영구 1.5배. 광고 가속(2배)과 곱해진다.
  - 배율은 첫 값이고 단일 출처는 `apps/deep_grove/lib/economy/products.dart`.
  - 상점은 스토어가 알려 준 가격을 그대로 보여 준다. **가격대는 아직 정하지 않았다** (§10-4).
  - 구매 복원은 상점과 설정 양쪽에 있다.
  - 출시 전: Play Console·App Store Connect 에 위 id 로 비소모성(관리형) 상품을 만든다.
- 결제는 Bloom Wave와 같이 `in_app_purchase`, 광고는 `google_mobile_ads`(보상형 단위만).

## 7. 성공 지표

`core_analytics`로 측정한다. 목표치는 첫 값이고 소프트 런칭 데이터로 조정한다.

| 지표 | 목표 | 측정 방법 |
|------|------|-----------|
| 첫 확장 도달률 | 첫 세션 안 70% | 설치 후 첫 세션 종료 전 `board_expanded` 이벤트 발생 비율 |
| 동굴 진입률 | D3까지 40% | 설치 3일 안 `cave_entered` 이벤트 발생 비율 |
| D1 / D7 잔존율 | 35% / 12% | 첫 실행일 대비 1·7일째 `session_start` 비율 |
| 보상형 광고 시청 DAU 비율 | 25% | 일별 `rewarded_ad_completed` 사용자 / DAU |

첫 확장 도달률을 1번에 둔 이유: 프로토타입이 검증하지 못한 것이 루프 지속성이고
(`proto_merge.md` 판정 기록), 그 루프의 첫 바퀴가 "첫 확장"이다. 여기서 이탈하면
확장 곡선·지대·수익 설계가 전부 의미 없다. 이 수치가 낮으면 테마 문서 §5의
시작 보드 크기·첫 확장 비용부터 고친다.

## 8. 제약 및 전제

- 게임 여부: **☑ 게임(Flame 사용)** / ☐ 일반 앱
- **오프라인 동작**: 전 기능 오프라인. 광고·결제만 네트워크가 필요하다.
- **서버/백엔드**: v1 불필요.
- **외부 서비스 의존**: AdMob(보상형), 스토어 결제. 로그인·푸시 없음.

### 8.1 상태 경계 **[확정]**

`docs/03-architecture.md` §3 게임 상태 분리 규칙을 이 앱에 적용한 결과:

| 무엇 | 어디 | 이유 |
|---|---|---|
| 보드 칸 점유·머지 판정·스폰 | **인게임** — 순수 Dart 모델(`lib/domain/`) + Flame 컴포넌트 | 프로토타입 `BoardModel` 이식. Flame 없이 단위 테스트 |
| 창고 자원·확장 단계·해금·IAP 보유 | **아웃게임** — Riverpod | 보드 밖 상태 (테마 문서 §8) |
| 둘의 접점 | 브리지 하나 — 산출원 탭/방치 산출은 "자원 산출" 이벤트로 나가고, 확장은 "보드 크기 변경" 명령으로 들어온다 | Flame 컴포넌트가 Provider를 직접 읽지 않는다 |
| 저장 | `core_storage` (key-value에 JSON 스냅샷) | 보드는 칸 최대 수십 개라 조회 쿼리가 필요 없다. drift 불필요 |
| 테마 정의(체인·확장 비용·확률표·보너스·창고 용량) | 앱 안 데이터(Dart 상수 또는 JSON asset) | 테마 추가 = 데이터 추가 (테마 문서 §8) |

### 8.2 방치 산출과 시계

- 방치 산출은 **기기 시계 기준 경과 시간**으로 계산한다. 서버 시간이 없다.
- 경과 시간이 음수(시계를 되돌림)면 0으로 본다. 시계를 앞당기는 조작은 **창고 용량이
  상한선**이라 한 번에 얻는 양이 묶인다 — 별도 방어는 두지 않는다. 오프라인 싱글 게임에서
  막을 가치보다 정상 사용자를 오판할 위험이 크다.
- 프로토타입 `proto_idle_visit`의 `World.advance`(실시간·오프라인 진행을 한 함수로 통일)
  방식을 참고한다.

## 9. 앱 이름 **[확정]**

| 층 | 값 |
|---|---|
| 스토어 표시명 | **Deep Grove** |
| 패키지·디렉터리 | **`deep_grove`** (`docs/03-architecture.md` §7 snake_case) |
| 번들 ID | `com.itparrot.deepgrove` (Bloom Wave `com.itparrot.bloomwave`와 같은 형식) |

**이유**: "깊은 숲" — 옆으로 넓히는 숲(grove)과 아래로 파고드는 깊이(deep)를 한 이름에
담는다. 숲이 아닌 다음 테마가 와도 "숲이 깊어진다 / 더 깊이 판다"로 이어진다.

**출시 전 확인**: (1) 양대 스토어 동명·유사명 앱, (2) 상표 충돌. 충돌 시 표시명만 바꾸면 되고
(부제 추가 등) 패키지 이름 `deep_grove`는 그대로 둘 수 있다. 번들 ID는 스토어 등록 전까지만 바꿀 수 있다.

## 10. 열린 질문

1. **보드 막힘** — 칸이 꽉 찼고 머지할 짝이 없고 확장할 자원도 모자란 상태가 가능하다.
   산출원이 하나라도 있으면 방치 산출로 언젠가 풀리지만, 산출원이 없는 초반에는 막힐 수 있다.
   해소 장치(아이템 판매/버리기 칸 등)가 필요한지 첫 테마 경제 시뮬레이션으로 확인한다.
2. **생성기 탭 제한** — 프로토타입은 쿨다운·에너지 없이 무한 탭이다. 정식에서는 빈 칸이
   유일한 제한이 되는데, 이것만으로 진행 속도가 조절되는지 본다. 에너지를 넣으면 수익 모델
   (§6)과 다시 엮이므로 v1은 넣지 않는 쪽을 기본으로 둔다.
3. **경제 수치** — 탭 산출량 vs 방치 산출량, 생성기 레벨별 확률표, 지대 보너스 배율, 창고 용량,
   §5 확장 비용. 전부 테마 데이터 값이고, §7 첫 확장 도달률을 맞추는 방향으로 잡는다.
4. **IAP 상품 구성·가격대** — 3번이 잡힌 뒤.
