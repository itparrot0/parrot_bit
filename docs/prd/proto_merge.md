# PRD — proto_merge (머지 게임 프로토타입)

- **문서 상태**: 확정 (2026-08-01, 기본값 그대로)
- **작성일**: 2026-08-01
- **대상 앱**: `apps/proto_merge` (프로토타입 — 릴리즈 CI 제외)

---

## 검증 가설

- **가설**: 그리드 보드에서 드래그드롭으로 같은 숫자를 합쳐 업그레이드하는 조작이,
  모바일 터치에서 오조작 없이 직관적으로 동작하고 반복하고 싶은 손맛이 있다.
- **검증 방법**: 원+숫자만으로 된 최소 그래픽 보드를 만들어 직접 플레이.
  (1) 드롭 판정이 의도대로 되는가 (2) 머지 순간의 피드백이 만족스러운가
  (3) 생성→머지 루프를 5분 이상 지루하지 않게 반복하게 되는가를 관찰.
- **판정 기준**:
  - **승격**: 조작 오류율이 체감상 무시 가능하고, 루프가 재미의 씨앗이 된다고 판단되면
    정식 앱 기획(테마·성장·수익모델)으로 진행.
  - **폐기**: 조작 자체가 모바일에서 답답하거나 루프가 지루하면 종료.
- **기한(타임박스)**: 2주 (2026-08-14까지)

## 게임 규칙 명세

### 1. 보드

- **격자**: 세로 화면 기준 **5열 × 6행 = 30칸**. 화면 폭에 맞춰 셀 크기 자동 계산.
- 각 칸의 상태: 빈 칸 / 아이템 / 생성기.
- 빈 칸은 옅은 배경 타일로 표시해 격자가 보이게 한다.

### 2. 아이템

- 표현: **원형 + 중앙 숫자** (레벨 = 숫자). 레벨별로 배경색만 다르게 한다.
- 레벨 범위: **1 ~ 5** (상수로 변경 가능). 최고 레벨 5는 더 이상 머지되지 않는다.
- 같은 레벨 2개를 겹치면 **레벨+1 아이템 1개**로 합쳐진다 (2개 소멸 → 1개 생성).

### 3. 생성기 (Generator)

- 초기 위치는 **최하단 행 중앙**이며, 아이템처럼 **드래그로 이동할 수 있다** (2026-08-01 변경).
- 표현: 사각형 + "G+레벨" 라벨 (아이템과 시각적으로 구분).
- **탭하면 자기 레벨과 같은 레벨의 아이템을 무작위 빈 칸에 1개 생성**한다 (G1 → 레벨 1, G2 → 레벨 2).
- **생성기끼리도 머지된다**: 같은 체인·같은 레벨 생성기를 겹치면 레벨+1 생성기가 된다. 생성기 최대 레벨은 **3**.
- 빈 칸이 없으면 생성하지 않고 생성기가 흔들리는 피드백을 준다.
- 쿨다운·충전·비용 없음 (프로토타입 범위 밖).

### 4. 드래그드롭 판정

조각(아이템·생성기)을 집으면 살짝 확대 + 최상위로 올려 드래그 중임을 보여준다.
드롭 시 **드래그 중인 조각의 중심이 속한 칸** 기준으로 판정한다:

| 드롭 지점 | 결과 |
|-----------|------|
| 같은 종류·같은 체인·같은 레벨 조각이 있는 칸 | **머지**: 레벨+1 조각 생성, 스케일 펄스 피드백. 아이템↔아이템, 생성기↔생성기만 가능 |
| 빈 칸 | **이동** |
| 서로 다른 종류의 조각 (아이템↔생성기) | **자리 교체(swap)**: 두 조각의 위치를 서로 바꾼다 (2026-08-01 변경) |
| 그 외 (같은 종류인데 레벨/체인 불일치, 보드 밖) | **스냅백**: 원래 칸으로 복귀 |
| 최고 레벨끼리 겹침 (아이템 5, 생성기 3) | 스냅백 (머지 불가) |

머지 횟수 통계에는 아이템 머지와 생성기 머지가 모두 포함된다.

### 5. HUD / 화면

단일 화면(홈 없음, 바로 게임 진입). 상단 HUD에:

- **최고 도달 레벨**, **누적 머지 횟수**
- **Reset 버튼**: 보드 초기화 (확인 다이얼로그 없음)

초기 배치: 생성기 1개 + 레벨 1 아이템 2개 (첫 머지를 바로 체험할 수 있게).

### 6. 범위 밖 (명시적 비범위)

저장/불러오기, 점수·목표·퀘스트, 사운드, 레벨 5 초과 콘텐츠,
아이템 판매/삭제, 튜토리얼, 수익화. — 전부 승격 이후 정식 기획에서 다룬다.

## 구현 방침 (아키텍처 문서 준수 사항)

- **Flame 사용**. 보드/아이템/생성기는 Flame 컴포넌트, 드래그는 `DragCallbacks`, 생성기 탭은 `TapCallbacks`.
- **머지 규칙은 순수 Dart 모델**(`BoardModel`: 격자 상태 + 이동/머지/스폰 판정)로 분리해 Flame 없이 단위 테스트한다. 컴포넌트는 모델 결과를 그리기만 한다.
- 인게임 상태는 전부 Flame/모델 내부에 둔다. 프로토타입이므로 Riverpod는 도입하지 않는다 (HUD는 Flutter 오버레이 + 콜백으로 충분).
- 패키지 의존: `core_ui`(테마·토큰)만 사용. 저장·네트워크·분석은 쓰지 않는다.
